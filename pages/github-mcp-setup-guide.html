Ask the Knowledge Vaults

Two ways to let your AI tool answer questions from the team knowledge vaults. Both work in Claude Code, VS Code and Antigravity.

Which one should I use?

Option A — Vault skill Option B — GitHub MCP server
GitHub account Not needed Required
Token / sign-in None Personal Access Token or browser sign-in
Setup Copy one folder One config entry per tool
How you ask Plain English — it knows the vault Name the repo in every question
Needs git installed (Mac, Linux and Windows all supported) Nothing installed

Use Option A unless you can't. It is simpler for the people asking questions and needs no GitHub access at all. Option B is the fallback when git isn't available on the machine, or your tool is too old to support skills.

Why we standardised on the skill

The deciding factor was authentication. GitHub's MCP server makes every single person create a personal access token before they can read anything — even though our vault repos are public. That is a setup hurdle for non-technical users, and tokens to manage and rotate indefinitely.

The skill needs none of that. It is one folder people drop in once, and it pulls the latest vault straight from GitHub each time they ask. No GitHub account, no token, no sign-in. It works in Claude Code, VS Code and Antigravity, on Mac, Windows and Linux — the only requirement is git.

It is also better day to day: people just ask in plain English, whereas with MCP they have to name the repo and repeat the ground rules in every question. MCP stays documented as a fallback for anyone who cannot install git.

The vaults

Each team has its own vault. Both options reach all of them:

Team Vault repo Skill How you invoke it
ABAP t-labs-buy/abap-wiki abap-wiki /abap-wiki {question}
Infor t-labs-buy/infor-wiki infor-wiki /infor-wiki {question}

Install only the vault(s) you need, or both if you work across teams — the AI picks the right one from your question, so the / command is only needed when you want to be certain. (Option B has no / command; you name the repo instead — see "How to ask" below.)

Option A — The vault skill

A skill is a small folder that teaches your AI tool how to answer from the vault. Because the vault repos are public, the skill keeps its own copy on your machine and refreshes it from GitHub every time you ask — so there is no token, no sign-in and no GitHub account, and answers are fast because the pages are read locally.

Step 1 — Get the skill folder.

The skill lives in the vault repo itself, at .claude/skills/abap-wiki/. Download that folder from GitHub, or ask the vault curator for it. It contains three files: 

abap-wiki/
├── SKILL.md
└── scripts/
    ├── sync-vault.sh      (macOS / Linux)
    └── sync-vault.ps1     (Windows)

The only requirement on your machine is git — check with git --version. If it's missing, install it from git-scm.com. The skill picks the right script for your operating system automatically.

Step 2 — Drop it in the right place for your tool.

Each tool looks for skills in its own folder. Copy the whole abap-wiki folder into the one that matches:

Tool Where the folder goes
Claude Code ~/.claude/skills/abap-wiki/
VS Code (Copilot) ~/.claude/skills/abap-wiki/ — the same folder. VS Code reads it directly, so if you already use Claude Code there is nothing more to do.
Antigravity ~/.gemini/config/skills/abap-wiki/

On Windows, ~ means C:\Users\{your name}\ — e.g. C:\Users\{you}\.claude\skills\abap-wiki\.

Copy-paste versions:

# Claude Code and VS Code (same folder)
mkdir -p ~/.claude/skills && cp -R abap-wiki ~/.claude/skills/

# Antigravity
mkdir -p ~/.gemini/config/skills && cp -R abap-wiki ~/.gemini/config/skills/

Restart your tool so it picks the skill up.

Working in a shared project? Instead of the personal folders above you can commit the skill into the repository everyone uses — .github/skills/abap-wiki/ for VS Code, or .agents/skills/abap-wiki/ for Antigravity and VS Code. Then teammates get it automatically with a git pull.

Step 3 — Ask.

Just ask in plain English. The AI recognises vault questions and uses the skill by itself:

"What did we decide about the credit auto-release job?"
"Which custom objects exist in the OTC workstream?"
"What's still open on integrations, and who owns it?"

If you want to be certain it uses the vault, name the skill: use the abap-wiki skill — {your question}. In Claude Code you can also type /abap-wiki {your question}.

What happens under the hood: the skill pulls the latest vault from GitHub (a few seconds the first time, instant after that), reads meta/index.md to orient itself, translates your wording to the vault's canonical names (so "Order-to-Cash" finds OTC), opens the relevant pages, and answers with citations — never from the raw/ folder, and never guessing when the vault is silent. Offline, it answers from the last synced copy and says so.

Option B — GitHub MCP server

This route gives your AI tool a phone line to GitHub's official github-mcp-server, which reads the repos live. There is nothing to install, but it needs a GitHub account, and you must name the repo in every question.

Before you start

  • The service already runs at https://api.githubcopilot.com/mcp/. You only tell your tool that it exists and prove who you are.
  • The vaults are public, so any GitHub account works — including a brand-new free one (github.com/signup). No invitation or org membership needed.
  • Despite "copilot" in the address, you do not need a Copilot subscription.

Claude Code

Heads-up: the browser sign-in does not work in Claude Code — it fails with "Incompatible auth server: does not support dynamic client registration". Use the token method below; it is the officially documented path.

1. Create a token. On github.com: profile picture → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token. Name it, and under Repository access choose Public repositories. Because the vaults are public it needs no extra permissions. Copy the token — it is shown once. Treat it like a password.

2. Add the server, pasting your token in place of YOUR_TOKEN_HERE: 

claude mcp add-json -s user github '{"type":"http","url":"https://api.githubcopilot.com/mcp/","headers":{"Authorization":"Bearer YOUR_TOKEN_HERE"}}'

(-s user makes it work in every session.) Verify with claude mcp list.

Optional: add "X-MCP-Readonly":"true" and "X-MCP-Toolsets":"context,repos" to the headers. The connection becomes read-only and drops from 44 tools to 16. Skip it if you also use this connection for issues and pull requests.

VS Code (Copilot)

Command Palette (Cmd/Ctrl+Shift+P) → "MCP: Add Server" → choose HTTP → address https://api.githubcopilot.com/mcp/ → name it github. Sign in with any GitHub account when the browser opens — no token needed here.

If your version lacks that command, run "MCP: Open User Configuration" and paste: 

{
  "servers": {
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/"
    }
  }
}

Antigravity

Settings → MCP Servers → Manage/Add. If it asks for JSON: 

{
  "mcpServers": {
    "github": {
      "serverUrl": "https://api.githubcopilot.com/mcp/"
    }
  }
}

If it offers no browser sign-in, create the same token as in the Claude Code section and add it: 

{
  "mcpServers": {
    "github": {
      "serverUrl": "https://api.githubcopilot.com/mcp/",
      "headers": { "Authorization": "Bearer YOUR_TOKEN_HERE" }
    }
  }
}

How to ask (Option B only)

The AI doesn't know which repo you mean, so every question must carry the repo name and the ground rules:

"Using the github tools, first read meta/index.md from t-labs-buy/abap-wiki, then answer from the vault pages (never from the raw/ folder) and cite which page you used: {your question}"

Save that sentence somewhere reusable — a prompt file at .github/prompts/abap-wiki.prompt.md in VS Code, or just a note you paste from. Swap in your team's repo from the vaults table.

Example — the same question, three ways

Take a real question: "What are the alternative ways to declare a work area in ABAP?" Here is what you actually type in each setup.

1. ABAP vault skill (Option A)

Ask it plainly — nothing else needed:

What are the alternative ways to declare a work area in ABAP?

Claude recognises this as a vault question and runs the skill on its own. To be explicit, name it instead: 

/abap-wiki What are the alternative ways to declare a work area in ABAP?

2. Infor vault skill (Option A, second vault)

Same pattern, different vault — you only change the command. If you have both skills installed, this is how you force the Infor one: 

/infor-wiki What are the alternative ways to declare a work area in ABAP?

This particular question belongs to the ABAP vault, so the Infor vault will correctly answer "the vault doesn't have this yet" rather than inventing something. That is the guardrail working — each skill only answers from its own vault. Normally you don't pick at all: just ask, and the right vault answers.

3. GitHub MCP server (Option B)

No skill is involved, so the question has to carry the repo and the rules every time: 

Using the github tools, first read meta/index.md from t-labs-buy/abap-wiki,
then answer from the vault pages (never from the raw/ folder) and cite which
page you used: What are the alternative ways to declare a work area in ABAP?

What a good answer looks like. For this question the vault holds the team's rules about work areas — the LS_ / GS_ naming prefixes, "use field symbols rather than work areas", "CLEAR the work area at the end of each LOOP pass", "internal tables with header line are not allowed" — cited from Standard - ABAP Naming Conventions and Standard - ABAP Performance Guidelines. It is not an ABAP language tutorial, so it should say the plain-syntax alternatives aren't recorded rather than filling the gap from general knowledge. An answer with no page citation means the tool skipped the vault — ask again.

Troubleshooting

Option A — skill

  • The AI ignores the skill — check the folder is in the exact location for your tool (table above) and that SKILL.md sits directly inside it, then restart the tool. Force it with "use the abap-wiki skill".
  • VS Code doesn't see it — update VS Code. Skill support arrived in recent versions; older builds ignore the folder entirely.
  • "could not clone" — you're offline, or git isn't installed. Check with git --version.
  • Windows: "running scripts is disabled on this system" — PowerShell blocked the script. It is meant to be run as powershell -ExecutionPolicy Bypass -File …\sync-vault.ps1, which the skill does automatically; if you ran it by hand, add that flag. Nothing needs to be changed permanently.
  • Answers look out of date — the skill reports offline (using cached copy) when it can't reach GitHub. Reconnect and ask again; it re-syncs on every question.
  • The local copy got into a bad state — nothing to do. The skill detects a corrupted copy and rebuilds it automatically, reporting repaired.

Option B — MCP server

  • "Incompatible auth server: does not support dynamic client registration" — you tried browser sign-in in Claude Code. Use the token method.
  • Your fine-grained token is rejected — create a classic token instead (Settings → Developer settings → Tokens (classic)) with the public_repo scope.
  • "Repository not found" — the repo name is misspelled. Check the vaults table.
  • The AI answers from memory — it skipped the tools. Ask again and say "using the github tools".

Either option

  • The AI quotes raw meeting transcripts — remind it: answer only from the synthesized vault pages, never from the raw/ folder.
