Hello, What you're looking at here is the complete setup behind our LLM Wiki Project. 

Every box on the screen is a real system we use today, and in the next few minutes you'll watch a real document move through every one of them.

But first, why did we build this?

On any team project, knowledge ends up scattered everywhere: meeting notes, PowerPoint decks, specification documents, email threads. A few weeks later, someone asks, "What did we decide about X?" The answer exists, but it's buried somewhere that nobody wants to search through.

The easiest way to picture our solution is as a library with a robot librarian.
There's a mail slot where you drop documents, a bell that rings when new mail arrives, a librarian who reads everything and files it onto the right shelves, and finally a reading room where the whole team can browse the knowledge.

The only thing a human ever has to do is drop a document into the mail slot. Everything else happens automatically. And in the end, anyone can ask the library a question in plain English and get an answer with the sources attached.

So here's the only human step in the entire pipeline.


A team member drops a document into a shared OneDrive folder. That's our mail slot. It could be meeting notes, a Word document, a PDF, a slide deck, or even a transcript.

Within about a minute, a small Microsoft service called Power Automate notices the new file. Think of it as a messenger watching the mailbox. 
As soon as something arrives, it picks up the document and carries it from the Microsoft world into GitHub.

GitHub is our vault—the wiki's permanent home—where every change is versioned and remembered.
Before it finishes, the messenger moves the original uploaded file into a Sent folder in OneDrive. 
That keeps the inbox clean and guarantees the same document is never processed twice.

The moment the file reaches GitHub, the alarm bell rings.
GitHub detects the change, spins up a fresh cloud machine, checks out a copy of the wiki, and runs our librarian — a Python script.
The Python script opens the document and extracts its text.

Before we hand anything to the AI, though, we give it a rulebook.
Inside the wiki is a file we call the Constitution. 

It tells the AI exactly how the wiki should be organized—which pages exist, how they're named, how they link together, and what counts as knowledge worth keeping.

We then send Claude three things:
	•	the Constitution,
	•	a map of the existing wiki,
	•	and the newly extracted document.
Claude reads all three, much like an experienced librarian, and returns its filing decisions.
The Python script then does the bookkeeping. It creates or updates wiki pages, refreshes the index, and records everything it changed in a processing log so we always know which document was read and which pages were updated.
Finally, everything is committed back to GitHub, and you can actually watch the updated files appear one by one.

So how does the team see all of this?
Every team member keeps a local copy of the wiki on their laptop. It quietly checks GitHub for updates every five minutes.
Most people browse the wiki using a free application called Obsidian — our reading room.
Pages link together just like Wikipedia, search is instant, and there's even a visual graph showing how all the knowledge connects. 
As soon as the latest changes are pulled, the new decision page appears automatically for everyone.

Now let's fast-forward a few weeks.
Someone who never attended that workshop wants to know:
"What did we decide about the custom approach?"
Instead of searching through folders or interrupting a teammate, they simply ask the wiki in plain English using Claude Code.
The assistant doesn't guess, and it doesn't search the internet.
It reads the actual wiki pages stored on that person's machine, and every answer has to include citations that point back to the exact pages it used.


So that's the complete loop we just watched.
A document dropped into a mail slot became organized, linked knowledge. And weeks later, that same knowledge became a fully sourced answer to a question.
